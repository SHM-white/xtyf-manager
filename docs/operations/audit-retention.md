# 审计日志分类、分级与清理

审计页面：`/admin/security`。管理员可组合筛选**业务类别**、**重要级别**和**结果**，默认只展示永久、严重和重要记录；“全部级别”仍可查看一般与低优先级日志。显示简化的中文操作名称，技术 endpoint 和目标路径保留在明细行，方便排障。

## 业务分类与重要级别

| 业务分类 | 主要范围 | 默认级别 | 保留 |
| --- | --- | --- | --- |
| 资金与发票 | 资金增删改审、发票上传/修改/导出、后台发票任务及失败记录 | **永久** | **永久，不受过期或行数配额清理** |
| 登录与权限 | 登录/退出、改密、业务授权、角色/停用/密码重置、成员导出 | 严重 | 365 天 |
| 资产与物资 | 资产、库存、借还、物资目录与操作 | 重要 | 180 天 |
| 成员与账号 | 成员创建、资料、分组、删除/恢复 | 重要 | 180 天 |
| 任务与项目 | 新建/编辑任务及项目、排期等 | 一般 | 90 天 |
| 协作与通知 | 消息、讨论、协作变更 | 一般 | 90 天 |
| 系统设置 | 外观、工作台设置等 | 低 | 7 天 |
| 未分类 | 尚未识别的 endpoint | 严重（保守） | 365 天 |

额外规则：**失败和部分成功的非财务操作升级为严重**；一般/低级别的删除、恢复、撤销、导出操作至少升为“重要”。不以路由 URL 中的自由文本猜测是否财务，而是通过已知稳定 endpoint 前缀判定。新增业务路由应更新 `classify_action` 和单元测试。发票/资金均为永久，包括失败的 API 请求、导出与后台任务。

级别控制保留期，业务类别帮助快速查询。当前只对**已落入 `security_audit` 的记录**生效；仅 GET 类型的普通页面读取不会凭空新增审计日志。此处“永久”指应用内的审计清理不会删除，**不是不可篡改、异地备份或满足特定法规的归档保证**；仍须做好数据库备份及访问控制。

## 历史数据与回滚

升级时为旧表添加 `category` 字段，并对现存日志进行**一次性无删除分类回填**，同时保留原有 `level` 兼容列。历史财务日志也自动变为永久。新的写入直接赋予类别/级别；结束请求时按实际结果复核，异步发票任务也保持永久。

默认**不自动清理**。旧版的定时或启动清理已经停用。清理操作必须在停止业务写入后、由管理员明确执行，并在删除前创建全新 SQLite 一致性备份：

```bash
python deploy/audit_maintenance.py --database /path/to/data.db
# 核对各级数量、保护数和拟删除数量
python deploy/audit_maintenance.py --database /path/to/data.db \
  --apply --backup /safe/path/audit-before-maintenance.db
```

## 自定义保留时间（配置文件或管理员页面）

**永久记录固定永久**，不会显示可编辑字段；其余四个级别可以独立配置 0～36500 天（0 表示该级别不因时间或容量约束删除）。更改保留期只影响以后人工执行清理时的判定，**保存设置本身不清理数据库**。

**方法 A：管理员页面。** 登录超级管理员账户，打开 `/admin/security` → **审计保留策略**，填写四个级别的天数并保存。值持久化到业务数据库的 `audit_retention_settings` 表，重启服务仍然有效；点击“恢复配置文件／环境变量设置”会删除管理员覆盖值并重新继承服务器配置。普通成员及项管没有权限读取或修改此策略。

**方法 B：服务器 JSON 配置文件。** 将仓库的 `deploy/audit-retention.example.json` 复制到业务库之外的受控路径，例如 `/etc/xtyf-manager/audit-retention.json`，内容：

```json
{
  "critical": 365,
  "important": 180,
  "normal": 90,
  "routine": 7
}
```

服务进程使用 `AUDIT_RETENTION_CONFIG=/etc/xtyf-manager/audit-retention.json` 指向该文件。文件可以只配置需要覆盖的级别；**不得包含 `permanent`**。所有值必须为整数，不允许负数、布尔值、小数、未知字段或超过 36500 天。不存在或格式错误时会拒绝生成清理计划，不会错误地使用危险默认值。JSON 配置不是部署时自动写入的，文件需由管理员自行放置并限制权限，避免随部署覆盖。

**生效优先级：管理员数据库设置 > JSON 文件 > 兼容旧环境变量 > 程序默认值。** 页面会标识每一级别当前值的来源。管理员“保存”一次性覆盖四个非永久级别；“恢复配置文件／环境变量设置”将取消覆盖。

保留期环境变量（`0` 禁用对应级别按时间和容量清理）：

- `AUDIT_RETENTION_DAYS`：严重，默认 365 天，兼容原有变量。
- `AUDIT_IMPORTANT_RETENTION_DAYS`：重要，默认 180 天。
- `AUDIT_NORMAL_RETENTION_DAYS`：一般，默认 90 天。
- `AUDIT_ROUTINE_RETENTION_DAYS`：低，默认 7 天。
- `AUDIT_MAX_ROWS`：默认 100000；仅可能淘汰尚允许清理的低优先级日志；**不删除财务、严重、重要、一般的未过期记录，也不删除设置为 0 天的低优先级记录**。设为 0 关闭容量约束。

维护工具还支持 `--config /etc/xtyf-manager/audit-retention.json` 显式指定文件。管理员数据库覆盖设置与维护工具共用同一个业务数据库，且 `--config` 仅指定 JSON 输入、不能覆盖数据库中已经保存的管理员设置。预览 JSON 输出包含各级别实际使用的 `retention_days` 和 `retention_sources`，请在执行 `--apply` 前核对。

`pending`、后台发票任务的审计引用和原请求引用链继续豁免；容量上限可能被永久或被保护记录超过。

如需保守重置，请使用 `--reset-classification --apply --backup <新文件>`。这一操作**只变更级别不删除记录**：财务继续永久保留，其他全为严重。回滚软件版本不能恢复此前已经手动清理的记录；必须从备份恢复。老版本程序不会识别新分类字段，勿让它和新版本同时向同一个库写入。
